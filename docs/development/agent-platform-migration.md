# 智能体平台迁移方案

状态更新（2026-10-27）：用户已授权正式迁移，核心实现和旧数据导入已完成，正在进行产品级验收。以下保留设计目标；实际完成项、证据与未完成门槛以[迁移验收报告](platform-acceptance.md)为准。

## 1. 迁移原则

- 保留账号 ID、密码散列、现有 JWT 配置、聊天历史和文件引用；不要求用户重新注册或复制旧文件。
- 新产品不保留每用户 Host、物理项目导航等旧执行模型。保留历史读取适配是为了数据可用，不是长期维持两套运行架构。
- 不把旧 Project 转成 Agent，也不把旧任务自动重新执行。新 Agent 定义需要创建、试跑和发布确认。
- 每阶段有可检查出口。自动恢复第一阶段就验证，发布前完整验收；不是先上线后补。
- 已授权实施；不自动提交或推送代码。数据导入保留源目录和数据库备份。

## 2. 逐模块保留、重构与替换

后端路径均相对于 `apps/server/src/orchmesh/`。

| 现有代码 | 处理 | 新职责或原因 |
| --- | --- | --- |
| `auth.py`、`security.py`、`accounts.py` | 保留核心 | 继续 JWT/pwdlib，移除登录预热 runtime 的回调；为 A2A 显式提供稳定 owner 上下文 |
| `bootstrap.py` | 调整 | 保留初始管理员与迁移；模型配置归平台，不为每个用户同步执行环境 |

| `config.py`、`cli.py`、Makefile | 调整 | 保留 .env 和简洁开发入口；增加数据库/执行配置，移除用户容器预热配置；不复制大量管理命令 |
| `storage.py`、Alembic | 拆分领域模型并迁移 | 保留账号和历史 ID；新增草稿、版本、任务/委派、记忆/知识、产物；不增加应用外键强制约束 |

| `dsh/rpc.py` | 复用传输 | JSON-RPC framing、退出/错误处理保留；进程归 task/attempt，不归登录用户；验证孤儿进程清理 |

| `dsh/navigation.py`、`projects.py` | 替换产品入口 | 新导航读业务数据库；旧目录所有权保留在历史文件绑定中，不启动 Workspace Controller 列广场 |
| `dsh/events.py`、`messages.py` | 收敛适配 | 复用必要解析；DSH 官方历史为消息事实源，不继续扩展第二套手写消息恢复器 |
| `activity.py` | 重构 | 请求校验/UI 操作复用；问题、输入、取消改为稳定任务 ID 与持久控制入口 |
| `workspace.py` | 保留安全读写边界并改定位 | 保留 dirfd/O_NOFOLLOW、类型/大小检查与 Range 响应；新文件以 artifact ID 授权定位 |

## 3. 建议目录边界

以下是模块目标，不要求一次性搬文件；遵循项目和官方组件的实际约定。

```text
apps/server/src/orchmesh/
  auth.py, security.py, logging.py
  agents/          # 草稿、发布版本、广场、评论
  tasks/           # 业务任务、DBOS 接入、提问与取消
  collaboration/   # 发现、工作复用、官方 A2A 适配
  runtime/         # DSH 进程/会话接管、沙盒供给
  artifacts/       # 持久成果、恢复材料、安全下载、旧引用
  memory/          # 用户偏好与用户-Agent 记忆
  knowledge/       # 共享/私人资料、修订、检索
apps/runtime/      # 可信 presets、DSH 官方插件组合与薄桥接
apps/web/src/features/
  auth/, chat/, conversations/, workspace/
  agents/, marketplace/, memory/
```

模块对外提供完整业务操作，例如发布版本、受理任务、委派工作、提交成果；不让路由直接操作 DSH/DBOS/A2A 内部表。

## 4. 分阶段实施与出口

### 阶段 A：先证明恢复与沙盒接入

进度：核心接入验证已通过，见[实测报告](../research/phase-a-validation.md)和可复现脚本。下列为本阶段原验收目标；报告明确区分整链验证、独立原语验证和仍需正式产品适配的部分。随后已获授权执行阶段 B 数据导入；实际结果见迁移验收报告。

使用隔离数据目录、测试数据库和固定 DSH 版本，保持当前账号与服务数据不动。

1. 锁定候选 DBOS/A2A 与当前 FastAPI/SQLAlchemy/Python 的可安装组合，检查官方 schema 初始化和 FastAPI lifespan。
2. 证明同一 PG 事务写 Task + 官方事务入队；提交前退出不产生已受理任务，提交后响应丢失能找回同一任务。
3. 打通一个 DSH Session：持久受理 → 执行 → SIGKILL → 重启 → 原 Session 自动继续。不能靠测试脚本替用户重新发整项提示。
4. 接官方 A2A Client/Handler/SQL store，子任务完成但通知丢失后，父任务通过持久结果继续。验证服务重启后还能发布协议更新，而非依赖旧内存 EventQueue。
5. 验证官方 SSH helper、文件/进程 provider、远端 rg/PTC、取消；普通聊天不分配 Docker，代码请求才分配。验证原 Session 在官方支持生命周期下进入远端执行，不调用私有字段。
6. 验证稳定恢复输入身份、旧 preset 绑定、可恢复提问、孤儿执行清理。任何无法由公开接口完成的能力必须回到设计决定，不继续叠补丁。

**出口：可重复的自动恢复和按需执行实验通过。** 失败时先修正方案，不把临时“标记 interrupted”当作阶段通过；不先大规模重写前端。

### 阶段 B：数据模型与迁移演练

- 通过 SQLite 在线备份或一致性停写快照备份现有数据库；保存迁移前行数、关键 ID、密码 hash 校验和文件清单摘要，检查备份可读。
- 清点 `.data/users/<user>/work`、`projects/<id>/work`、`dsh`、`config` 及引用。凭据不进入日志、仓库或 Agent 定义。
- 在演练库把账号、会话、历史 Run、项目目录所有权迁入 PostgreSQL。保留 ID 和时间；适配 SQLite/PostgreSQL 类型差异，校验唯一键和每条 owner。
- 同一 database 内分业务 schema 与 DBOS schema，官方 A2A 表采用独立命名空间/受支持配置。第三方 schema 升级走其官方流程，不手改内部表。
- 为旧文件生成稳定旧目录绑定，维持 `/workspace`、`/workspaces/<id>`、`/project-workspaces/<id>/work` 的原会话解释。新任务同名路径不能覆盖旧含义。
- 旧对话建议作为可读历史保留；用户要继续时创建新任务，显式引用选定历史上下文及授权文件。旧会话不会被恢复器当成新平台未完成任务自动执行。

**出口：登录、历史读取与旧链接校验一致，迁移可重跑且不重复创建账号/引用。** 不要求为新目录规范搬动原文件。用户若要求旧会话原地续聊，应单独验证旧 preset 和工具配置，不隐含承诺。

### 阶段 C：任务内核与 Agent 产品功能

- 接受任务、动态协作、持久问题/回答/取消，使用阶段 A 已验证的恢复适配。
- 完成 Agent 草稿、试跑、确认发布、不可变版本、权限与评论；统一助手通过同一能力目录选择协作者。
- 记忆和知识按 owner/agent/version 分区；新任务隔离私人状态。检索范围先授权再搜索，自动记忆候选可查看修改删除。
- 产物提交与恢复材料独立于沙盒；任务结束或空闲回收环境，成果仍可下载。
- 接现有页面组件与新业务 API；保留布局风格，不把公开协作者调用接到旧审批 checkbox。

**出口：正常业务链路可用，同时继续跑恢复回归；不能以“功能多”替代恢复验收。**

### 阶段 D：真实验收与切换

先用确定性模型/计数工具构造准确故障点，再按用户授权用现有管理员与项目真实模型验收。测试对话/Agent 明确标记，保留原数据。

正式切换前停新受理并让旧任务完成，确认无仍在执行的用户容器；再次一致性备份、迁移校验，再启动新服务。此过程是后续实施动作，不在本轮执行。发布首版必须通过下表。

### 阶段 E：删除旧执行链路

新链路通过后删除用户登录预热、用户 Host 池、Workspace 业务导航、进程内 pending Map、新消息 Pi 双重转换及过时配置。更新 README、AGENTS、实际架构和运维文档。保留旧数据读取需要的最小引用适配与备份。

回滚只在明确检查点执行：新系统尚未接纳写入时可回原快照；有新数据后先停写并导出/迁移新增数据，不能直接切回旧 SQLite 丢弃新任务。不要维护长期双写来掩盖切换风险。

## 5. 首版发布验收矩阵

| 故障/场景 | 验收证据 |
| --- | --- |
| 普通登录、聊天、历史、广场 | 不启动用户 Docker；仅实际代码阶段申请任务沙盒 |
| 同账号/不同账号并发调用同一 Agent | 独立任务和 Session，私有文件、记忆、上下文不串用 |
| Task 提交前/后进程退出、客户端重试 | 不丢已受理输入，不重复创建工作；参数冲突明确拒绝 |
| DSH 模型流中 SIGKILL | 自动恢复原目标/版本，显示恢复状态，允许未提交 token 缺失 |
| API 退出而 Node 未退出 | 确认停止或接续旧执行，不能两个 Host 同写 Session |
| 接管中再次 SIGKILL | 同一任务不出现重复委派、重复答案或双执行者 |
| 子任务完成但通知未送达 | 读取已保存结果，父级继续；计数工具证明未重做 |
| Shell 已写文件但结果未知 | 核对输出/执行记录，不盲重放；无法证明则显示阻塞原因 |
| 沙盒丢失 | 新环境从持久输入/恢复材料继续；原交付文件仍可下载 |
| 提问时服务重启、答案重复提交 | 原问题继续可答，一份答案只被业务消费一次 |
| 用户停止后服务重启 | 取消意图保留，不自动恢复；真实子进程停止可核查 |
| 执行中发布新版本/更新知识 | 原任务仍使用绑定版本/修订；撤销权限时明确阻塞 |
| 并发同工作、父子循环委派 | 复用工作结果；不同工作允许；无祖先等待死锁或队列饥饿 |
| 文件提交后、完成通知前崩溃 | 成果身份不重复，恢复能补完成状态，不重做整项任务 |
| 浏览器断开再连接 | 任务继续；快照 + 后续事件一致，已终态可读结果 |
| 真实报告任务 | 交付 report.md、report.html、sources.json，可预览下载、来源可核验 |

真实报告实例见[需求验收](../product/agent-platform-discovery.md#首个具体验收任务)。真实模型至少覆盖正常协作、模型执行中重启、子任务完成通知丢失、生成文件期间沙盒丢失，并结合浏览器检查。模拟故障测试、真实模型验收、浏览器检查分别报告，不能互相替代。

## 6. 仍需验证而非让用户猜的问题

1. DBOS 事务入队、A2A SQL 状态与 DSH 文件之间的精确对账窗口：同库不代表跨所有存储原子。
2. 官方 A2A Handler 的执行适配在请求结束/重启后如何继续更新原任务；不能依赖内存 registry。
3. DSH 恢复驱动去重、continued/timed 提问与原版本 preset 注册的公开 API 组合。
4. 官方 SSH 制品部署、按需初始化、远端执行路径覆盖和断线后清理确认。
5. 中文知识检索和上传格式解析的成熟组件选择；用真实文档样本决定，不先承诺任意格式。

以上通过小型接入实验解决，不新增用户审批层、用量额度或预编排需求。若选型不能满足首版恢复目标，先更新架构提案说明证据与替代方案，不能悄悄降低验收标准。
