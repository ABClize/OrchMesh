# OrchMesh 前端体验设计提案

状态：用户已批准并于 2026-10-27 实施。本文保留设计决策；实际实现、验证与剩余边界见[实施与验收记录](../development/frontend-observation-acceptance.md)。
依据：[产品需求](agent-platform-discovery.md)、[多智能体观测契约](../api/multi-agent-observation.md)，以及当前 App、Chat、ActivityPanel、Library、TaskInputs、Workbench、Delivery 的源码。当前诊断属于代码与信息架构审查，未登录检查实际页面。

## 1. 核心判断

用户首先要知道：我交代了什么、工作进行到哪里、是否需要我、结果在哪里。之后才是哪个智能体参与、发生了哪次工具调用。

因此采用“对话为主、协作为可展开的工作现场、执行记录逐层深入”的结构。调用图用于解释实际协作，不成为编辑工作流或编排智能体的画布。

当前主要问题与调整：

| 当前实现 | 体验问题 | 调整 |
| --- | --- | --- |
| ActivityPanel 在消息区上方遍历任务、显示 prompt 与原始 status | 内容持续增长；身份、目的、状态难区分 | 聊天只留紧凑运行摘要；完整信息进入协作视图 |
| 提问夹在所有任务之间，所有提交共享 pending | 需要用户介入的内容缺乏优先级；无关问题被锁定 | 待回答入口常驻；按任务和问题批次独立提交 |
| TaskInputs 常驻完整文件输入框 | 对话空间被低频操作占用 | 附件入口靠近输入框；上传后用材料条展示 |
| Library 弹窗同时装广场、草稿、记忆、知识、评论 | 发现、管理、编辑混杂，长表单和嵌套弹窗干扰定位 | 智能体库、知识与记忆分离为页面；编辑草稿为独立详情 |
| 文件说明暴露目录、沙盒和迁移细节 | 用户必须理解实现才能找文件 | 默认展示“任务材料 / 交付成果”；历史工作目录保留在次级入口 |
| 独立文件侧栏继续叠加观测侧栏的潜在方案 | 页面容易出现四列，聊天被挤窄 | 一次只打开一个辅助面板；协作另有主区视图 |

## 2. 页面与导航

左侧约 224 px，保留品牌、新对话、对话列表与项目组织。新增清晰的“智能体库”“知识与记忆”入口，代替并排的长按钮。创建智能体放在智能体库内部作为主操作；选定智能体后显示身份，再开始对话。项目组织与历史目录兼容保留，不改数据模型。

对话顶部保留标题与智能体身份，提供“对话 / 协作”视图切换和“文件”入口。模型思考设置降为次级设置操作。切换视图不卸载正在运行的聊天连接，不丢失输入草稿和阅读位置。

- 对话：消息、结果、输入框；一条运行摘要，例如“3 个智能体参与 · 1 次调用执行中 · 1 项待回答”。点击进入协作或定位问题。统计明确限定当前运行。
- 协作：范围选择、调用关系图或等价列表、选中对象详情。默认进入时选最新根调用；用户主动选旧运行后保持选择，新运行出现只提示，不强制跳转。
- 文件：复用现有预览和下载，区分上传材料与交付成果。文件来自选中调用时显示来源，可返回调用。聚合所有成果需要按现有文件接口能力核查，不能将 graph 当作文件清单。
- 智能体库：广场与我的智能体两个子视图；卡片只展示名称、职责、发布状态和主要动作，评论移至详情。我的智能体明确区分“编辑草稿 / 试运行 / 发布版本”，发布仍需现有确认流程。
- 知识与记忆：两个独立子视图；列表、详情与新增入口。关闭和删除效果依据后端真实语义另行核对，本轮不擅自承诺历史数据删除或追溯修改。

## 3. 协作视图

桌面宽屏：左侧应用导航，中部调用图，右侧约 340–400 px 的检查面板。1100 px 以下详情替换图区域，提供“返回协作”；手机改为“智能体列表 → 调用列表 → 调用详情”，不压缩整张图。

顶部范围为“本次运行 / 其他运行 / 全部运行”。“全部运行”实际指当前对话的全部根任务，不是账号全局。每轮用根调用目标摘要与创建时间识别，不暴露 UUID 作为主标题。

### 聚合图

- 节点代表 Agent 定义，标题为名称，下方是调用次数及状态计数，如“3 次调用 · 1 执行中 · 2 已完成”。不把一个混合状态节点染成单一成功或失败状态。
- 调用关系采用页面内的组件，按调用方归组、向下展示被调用方。反向调用和自调用分别显示为关系行，不递归展开，不假定为树；无画布、缩放或拖拽。状态更新保留当前选择。
- 边显示方向和调用次数。点击边筛选该 source → target 的调用；反向关系独立显示。已完成的边保持可见。
- 点击节点展示它的调用列表，即使只有一次，也在面板顶部保留调用身份；可直接展开唯一调用详情。
- 列表作为与图等价的可访问视图，支持键盘操作。密集关系由列表阅读，不以缩小文字解决。
- 等待依赖不增加第二套连线：详情里显示“正在等待：资料研究 / 调用 2”，可跳到被等待的任务。

### 调用列表与详情

节点列表按创建顺序显示“调用 1 / 2 / 3”、目标摘要、活动状态、时间、版本。编号只在当前筛选范围用于识别，真正身份始终是 task ID。边列表同时显示父调用，避免同一 Agent 多次委派时混淆。多种历史名称在各次调用中保留。

选中一次调用后：

1. 顶部：冻结名称、目标、活动状态、上级调用、创建时间；版本和 ID 折叠到“技术信息”。
2. 待回答时：问题优先显示，提供已有建议选项与自定义回答，提交绑定 task ID 和 callId。提交中只锁定本批次；失败保留输入。答案被接纳后刷新真实快照，不自行宣布任务恢复执行。
3. “输出”：复用当前消息投影与 Markdown/工具展示，使用独立只读运行上下文，不能覆盖主聊天 store。
4. “执行记录”：按 turn / step / tool 分组，参数与输出默认折叠；用 seq 排序。没有结果的工具显示“尚未记录结果”，不自动判成功或失败。
5. “文件”：显示该任务交付文件，可预览和下载；空态为“尚无交付文件”。

图和调用列表不提供“重试任务”“取消子任务”“修改计划”等尚无接口的操作。停止操作留在对话层，并明确是停止当前运行，沿用现有后端语义。

## 4. 状态语言与异常

| 数据 | 用户文案 | 展示位置 |
| --- | --- | --- |
| queued | 排队中 | 调用状态 |
| executing | 执行中 | 调用状态 |
| waiting_user | 等待你的回答 | 摘要提醒与问题卡 |
| waiting_dependency | 等待协作者 | 调用状态与依赖列表 |
| resuming_or_transitioning | 正在衔接执行 | 调用状态；说明暂时没有实时输出 |
| completed / failed / stopped | 已完成 / 失败 / 已停止 | 调用状态，失败附真实摘要 |
| 未识别 activity / waiting | 等待中或状态待更新 | 保守回退，不强行猜等待原因 |
| 网络中断 | 连接中断，正在重连 | 独立连接提示；保留已有内容 |
| log_available=false | 执行记录尚未可用 | 记录空态，不提示任务失败 |
| unavailable | 暂时无法读取记录，正在重试 | 记录提示，保留游标和内容 |
| 404 | 无法访问此调用 | 详情局部错误，允许返回 |
| unauthorized | 登录已过期 | 统一登录流程，停止无效订阅 |

不显示虚构进度、费用、恢复次数；创建时间不标成开始执行时间。usage 缺失时不显示零 Token；第一版不计算跨尝试总消耗。实时输出和持久记录分区展示，不拼接成重复消息。

## 5. 视觉规范

延续现有 Geist / 中文系统字体与中性灰配色，不引入另一套组件皮肤。正文 14 px，辅助信息 12 px，页面标题 20 px；正文保持舒适行高。用留白、分组标题和细分隔线建立层级，避免每条信息一张卡片。

强调色只用于选择；执行、等待、失败搭配图标和中文文字，颜色不作为唯一线索。避免所有连线持续流动和节点呼吸动画。新状态更新不抢焦点，尊重减少动画设置。

输入框与待回答表单是不同语义：前者向主助手交代任务，后者回答某个调用的问题；不能通过将答案发送进主聊天代替 answers 接口。

## 6. 数据与组件职责

建议新增 observation 功能模块，复用现有 Button、Tabs、Sheet、Resizable、Markdown、文件预览和 fetch-event-source。图布局库在实施时评估成熟方案，验证双向边、自环、键盘与大图表现后选择，不在本轮引入依赖。

- ObservationWorkspace：范围、视图和选择状态；不承担执行调度。
- AgentGraph / AgentCallList：同一 graph 快照的两种展现，节点只用不透明 nodes.id。
- CallInspector：task_ids / calls.id 定位详情，不能把节点 ID 当 task ID。
- TaskQuestions：可被摘要入口与调用详情复用，答案归属始终是原任务。
- ExecutionHistory：事件分页、去重、分组，游标与任务绑定。
- observation 数据适配层：生成的 API 类型、查询、SSE 生命周期；主聊天状态仍由现有 assistant-ui runtime 管理。

观测视图可见时一条 graph 流，选中调用至多一条 task 流；隐藏详情时关闭日志流，退出对话时全部取消。图快照整体替换，连接在任务结束后仍继续观察下一轮。主对话摘要若独立保持图订阅，应共享同一连接，不能重复订阅。

任务详情 snapshot 整体替换，历史按 task_id + seq 去重，始终用 next_after 推进，包括空页；done 后关闭任务流，unavailable 保留数据并退避。切换任务清理旧请求，防止迟到响应污染新详情。现有 connectEvents 只处理 update，不能直接用于 graph / snapshot / history，需要明确独立适配协议。令牌只放 Authorization header。

问题的数量不能从 waiting_user 调用数推断：图摘要显示“X 次调用待回答”，只有读到问题详情才能显示具体问题数。历史视图的作答权限须遵循现有只读与归属规则，不能因有问题数据就开放写操作。

## 7. 实施顺序与评审验收

第一步：调整对话顶部与材料入口；统一待回答交互；接入协作列表、调用详情、真实状态与文件。列表先闭合完整阅读路径。

第二步：在相同数据模型上加入聚合图、范围切换与执行记录；补齐重连、空页游标、反向边、自环、多版本与混合状态。

第三步：拆分智能体库与知识记忆页面，整理草稿编辑与发布流程。所有步骤沿用现有 API，不改变执行所有权。

确定性验收：聚合节点不会误传任务接口；切换详情无串数据；回答准确绑定问题；空事件页推进游标；重连不重复历史；切换/退出释放请求；错误与空态不同；选择旧运行不被新快照抢走。

浏览器验收：1440 / 1024 / 390 px 的图与详情路径、键盘焦点、长中文目标和大量调用、文件返回路径、待回答提交失败保留输入。真实模型验收另行覆盖一个 Agent 多次调用、并行协作、待回答与交付成果；不以原型示例代替真实执行。

本轮评审重点：认可“对话 / 协作”双视图吗；单次调用是否适合右侧检查面板；智能体库与知识记忆独立页面是否符合使用习惯。随附交互草图用于评审这些结构，所有示例名称、状态与输出均为演示数据。

## 2026-10-27 组件式视觉修订

按用户最新要求，协作关系使用普通 React 组件 `AgentRelations`，移除 React Flow / Dagre 与画布交互。调用方卡片包含委派关系行，智能体按钮选择聚合记录，次数按钮选择该方向的真实调用；桌面在所属关系组内展开详情，手机进入单列详情并提供逐层返回。循环、自调用及孤立节点均可呈现。

复用现有 Affect UI 免费 Button、Thinking Loader，以及输出中的工具调用卡片。蓝紫色表达关系与选择，绿/琥珀/红表达完成/等待/失败；文本与图标同时表达状态。只有 executing/running 的调用关系播放流动提示，等待与历史完成记录不播放。展开使用短距离淡入，尊重 prefers-reduced-motion。主题变量和组件样式集中在 observation.css，状态与身份显示集中在 ObservationStatus.tsx。
