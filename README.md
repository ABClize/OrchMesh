# OrchMesh

**A workspace for agents. A network for collaboration.**

OrchMesh 是一个**开源、自托管的多用户智能体工作空间**。

你可以直接在浏览器里向智能体交代任务，让它读取文件、执行命令、修改内容，并实时查看工作过程。每个人都有独立的工作环境和会话，不必共用账号或工作目录。

OrchMesh目标不止于「一个人和一个智能体聊天」，而是让**不同能力的智能体能够连接、分工、协作**，共同完成更复杂的任务。

## 从聊天，到真正做事

- **交代任务，而不只是提问**：智能体可以使用 Shell 和文件工具，在自己的工作空间里完成实际操作。
- **每个人都有独立空间**：用户的文件、配置和会话分别保存，互不混用。
- **随时查看执行进度**：回复和工具执行过程实时呈现在网页中；断开连接后重新进入也可以查看任务状态。
- **保留工作上下文**：会话与工作文件持续保存，方便继续之前的任务。
- **轻量、自托管**：一个 FastAPI 服务提供网页、登录和聊天接口，运行数据保存在自己的服务器上。

## 让智能体一起完成任务

一个复杂任务，往往需要不同的专长。OrchMesh 希望让智能体像团队成员一样协作：各自完成擅长的部分，再把结果交给负责统筹的智能体。

例如，你只需提出一个目标：

> 帮我调研一个产品方向，分析竞品，并整理成一份可执行的方案。

未来可以由多个智能体分工处理：

```text
你：提出目标
    │
    ▼
主智能体：拆解和协调任务
    ├── 研究智能体：收集资料与竞品信息
    ├── 分析智能体：整理数据与关键结论
    └── 文档智能体：汇总形成方案
    │
    ▼
统一返回结果与执行过程
```

**开发状态说明：** 上述跨智能体分工与任务委派是 OrchMesh 的发展方向，**当前版本尚未提供 Agent 间自动调用**。现阶段已支持多用户隔离、单用户智能体执行、会话持久化与实时交互。后续会在这一基础上逐步增加智能体发现、授权和协作能力。

## 执行引擎

新对话使用 **DeepSeek Harness 0.2.1-rc.3**。保留现有聊天界面、登录与每用户 Docker 工作区，支持流式回复、Shell/文件操作、停止与历史恢复。

执行层统一使用 DSH；已移除旧 Pi 运行时，磁盘遗留文件作为备份保留。已接入工具审批、提问、输入队列及子任务过程面板；定时提问、独立继续子任务和调度界面尚未接入。运行语义与复用边界见 [DSH 执行层](docs/architecture/dsh-runtime.md)。

## 项目与会话管理

侧栏“新建项目”创建平台管理的独立文件夹；选择项目后新建会话使用官方 Workspace 成员关系，同项目会话共享文件。

- 会话菜单支持重命名、置顶、归档/恢复和从已完成历史创建分支；分支继承历史与原工作目录。归档会清除置顶，历史只读。
- 项目支持重命名和“移除项目（保留文件和会话）”。移除仅删除官方登记，原会话进入“未分组”，文件、历史和下载引用保留。
- 项目目录位于 `.data/users/<user-id>/projects/<project-id>/work/`，容器内为 `/workspaces/<project-id>`；默认目录是 `/workspaces/default`。`/workspace` 是当前目录的别名，保留既有文件引用。
- 会话分组由官方工作目录成员关系决定，不提供跨目录的纯分组移动或项目归档。旧历史 cwd 不匹配的会话显示为未分组，仍使用原文件目录。
- 本版只支持服务器管理的文件夹，尚不支持选取任意宿主路径。名称不参与磁盘路径；运行时部分管理操作需要先停止任务。

## 审批、提问和运行控制

- 发送前可勾选“本轮工具审批”（网页默认开启）。工具执行会等待“仅允许这一次”或“拒绝”，子任务同样适用；关闭后沿用容器内自由执行。
- Agent 调用 `ask_user_question` 后显示选项及自定义回答。所有题目回答完整再提交；关闭页面不会代替你作答。
- 运行面板可“加入队列”或“插入下一步”；排队消息可编辑、移除或提前执行。实际接纳和执行顺序由 DSH 管理。
- 子任务面板显示状态、过程和停止按钮；任务完成后仍可查看已持久化的本地子任务历史。
- 停止会取消等待与待处理输入。页面重连可继续回答；后端重启不会自动恢复未完成任务。

## 文件预览、交付与思考设置

点击聊天页的 **工作区文件** 浏览当前账户的文件；同一项目的各对话共享工作目录。桌面端会话列表、聊天与工作区并排，左右两处分隔线均可拖动调整宽度；目录保留在预览上方，多文件使用标签切换。收起工作区保留打开的标签，退出账户后清空；刷新页面不恢复这些临时标签。窄屏使用抽屉。支持 Markdown、文本/代码、常见图片、PDF 和自包含 HTML 预览。可以要求智能体“生成文件并交付给我”，它调用 DSH 官方 `present` 后会显示可预览、下载的文件卡片，刷新后仍保留。

- 单个文件下载上限 20 MiB，文本预览上限 1 MiB。Office 等格式暂只下载。
- HTML 使用隔离预览，禁用脚本、外部资源和表单；Markdown 不加载外部图片或启用链接跳转。
- 卡片指向工作区的当前文件，不保存交付时快照；文件被修改或删除后，卡片也会反映当前状态。
- 打开已有对话，通过标题旁的 **思考** 设置选择模型默认或模型支持的等级；下一次发送生效，运行中不可修改。此设置会改变模型请求。

自定义兼容网关需在 `.env` 声明实际支持的思考能力。例如支持 DeepSeek 思考协议的网关：

```dotenv
ORCHMESH_MODEL_REASONING_EFFORTS='{"off":null,"high":"high"}'
ORCHMESH_MODEL_THINKING_FORMAT=deepseek
```

修改后重启服务。不支持该协议的供应商不要照抄；未声明能力时仅提供“模型默认”，不假装通用开关。

## 快速开始

需要 **Linux、Python 3.12、uv、Node.js 24、npm 和 Docker**。

在仓库根目录运行：

```bash
make setup
```

编辑自动创建的 `.env`，设置管理员账号和模型：

```dotenv
ORCHMESH_BOOTSTRAP_ADMIN_EMAIL=you@example.com
ORCHMESH_BOOTSTRAP_ADMIN_PASSWORD='设置至少12个字符的密码'

ORCHMESH_MODEL_BASE_URL=https://your-provider.example/v1
ORCHMESH_MODEL_API=openai-completions
ORCHMESH_MODEL_API_KEY='your-api-key'
ORCHMESH_MODEL_ID=your-model-id
```

然后启动：

```bash
make run
```

访问 **http://127.0.0.1:8000**，使用配置的管理员账号登录即可。

> 模型配置也可以暂时留空，之后由用户单独配置。以上环境变量中的模型信息仅同步给初始管理员，不会自动共享给其他用户。完整选项见 [`.env.example`](.env.example)。容器内访问宿主机模型服务时，请使用容器可达的地址，而不是 `localhost`。

## 邀请朋友使用

OrchMesh 不开放自助注册。管理员可以通过命令创建账号：

```bash
uv run --directory apps/server orchmesh create-user friend@example.com
```

朋友登录后会进入自己的独立工作空间，不会看到其他用户的文件、配置或聊天记录。为其单独配置模型（交互输入 Key，不出现在命令行）：

```bash
uv run --directory apps/server orchmesh configure-model friend@example.com --base-url https://your-provider.example/v1 --model your-model-id
```

管理员模型仍以 `.env` 为准，每次重启同步；管理员密码只在首次创建时使用。

## 常用命令

| 命令 | 用途 |
| --- | --- |
| `make setup` | 安装依赖并构建运行环境 |
| `make run` | 构建网页并启动服务 |
| `make dev` | 启动开发模式和热更新 |
| `make check` | 检查代码质量与类型 |
| `make test` | 运行自动化测试 |

服务在终端前台运行，使用 **Ctrl+C** 停止。开发模式默认访问 `http://127.0.0.1:5173`。

## 当前定位

OrchMesh 目前面向**自己与少量可信朋友**使用，而不是向陌生用户开放的公共托管服务。智能体具备命令执行和文件访问能力，容器隔离不等于完整的恶意代码沙箱。远程访问前请配置 HTTPS，并妥善保护服务器及用户凭据。

平台数据默认位于 `.data/`。备份时请同时保存数据库和每位用户的工作目录。

更多实现和调试信息见 [开发文档](docs/development/implementation.md)。
